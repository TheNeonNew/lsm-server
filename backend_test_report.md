# Backend Test Report

## Обзор
Проведено тестирование backend-сервиса LSM после рефакторинга архитектуры: внедрена JWT-авторизация, добавлен слой `repository`, введены контроллеры, реализованы миграции схемы и настроено автоматическое тестирование через Jest.

На момент отчёта проект прошёл все основные проверки и показывает стабильную работу ключевых маршрутов.

## Исправления и улучшения
- реализована JWT-авторизация через `jsonwebtoken`;
- middleware `authenticate` проверяет `Authorization` и поддерживает формат `JWT <token>`;
- введён слой `repository` для SQL-запросов и отдельный слой `controller` для HTTP-обработки;
- добавлены миграции SQL-схем в `src/db/migrations` и `src/db/migrationRunner.ts`;
- добавлен централизованный `errorHandler` и корректные JSON-ответы на ошибки;
- тесты охватывают модули репозиториев и интеграционные API-запросы.

## Функциональное тестирование API

### Проверено
- `/api/health` — работает, возвращает `200`.
- `/api` — возвращает информацию об API и список доступных endpoint.
- `/api/auth/register` — регистрация нового пользователя, проверка уникальности email, возврат `201`.
- `/api/auth/login` — вход по email и паролю, получение JWT.
- `/api/equipment` — CRUD-операции защищены JWT и возвращают ожидаемые результаты.
- `/api/statistics` — выводит агрегированные метрики и данные для графиков.
- `/api/notifications` — формирует уведомления базируясь на датах обслуживания и срока замены компонентов.
- `/api/logs` — возвращает записи сервисных операций.
- `/api/data/export` и `/api/data/import` — корректный экспорт/импорт данных.
- `/api/data/seed` и `/api/data/clear` — наполнение и очистка базы работают стабильно.

### Результаты
- Успешная регистрация и вход пользователей.
- Защита маршрутов работает: без JWT возвращается `401`.
- Корректная работа CRUD-операций для основных сущностей.
- Статистика возвращает структурированные данные, готовые для визуализации.

## Интеграционное тестирование

### Проверено
- выполнение миграций перед стартом приложения;
- создание, чтение и обновление данных в таблицах `Equipment`, `User`, `Component` и `Maintenance`;
- сохранение операций в `ServiceLog`;
- получение данных через контроллеры и маршруты.

### Результаты
- все тесты Jest прошли успешно;
- структура `route -> controller -> service/repository -> db` работает стабильно;
- SQL выполняется корректно, параметры передаются безопасно.

## Тестирование безопасности

### Проверено
- JWT-авторизация вместо устаревшего Base64-токена;
- нормализация email при входе и регистрации;
- хеширование паролей SHA-256 перед сохранением;
- проверка валидности токена и срока действия;
- единый JSON-ответ на ошибки.

## Выводы
- backend стабилен и протестирован на ключевые сценарии;
- архитектурный рефакторинг завершён: добавлены контроллеры, репозитории, миграции и автоматические тесты;
- приложение готово к дальнейшему расширению и интеграции с фронтендом.

## Рекомендации
- хранить `JWT_SECRET` в безопасном окружении, а не в коде;
- добавить тесты для негативных сценариев авторизации и прав доступа;
- настроить HTTPS на уровне инфраструктуры для безопасной передачи JWT.
