# 4.5.2 Архитектура программного кода

## Обзор архитектуры
Проект построен как модульный Express backend с разделением на уровни:
- `src/server.ts` — точка входа, инициализация Express, запуск миграций и регистрация маршрутов.
- `src/routes/*` — маршрутизация по предметным областям, проксирование запросов в контроллеры.
- `src/controllers/*` — обработка HTTP-запросов, валидация входящих данных, управление ответами.
- `src/repositories/*` — слой доступа к данным и SQL-запросов.
- `src/services/*` — бизнес-логика, нормализация данных и координация операций.
- `src/db/*` — подключение к SQLite, миграции, история версий.
- `src/middleware/*` — JWT-аутентификация и централизованная обработка ошибок.
- `src/models/*` — типы и DTO для сущностей.
- `src/seed/*` — загрузка/экспорт/импорт/очистка тестовых данных.
- `tests/*` — автоматические модульные и интеграционные тесты на Jest.

## Компоненты и взаимодействия

### Сервер и маршруты
- `src/server.ts` создаёт Express-приложение, подключает JSON-парсер и маршруты, затем выполняет миграции перед стартом.
- Базовый путь `/api` направляет на `src/routes/index.ts`.
- Основные маршруты:
  - `/auth` — регистрация и вход.
  - `/equipment`, `/components`, `/maintenance`, `/users` — CRUD-эндпоинты.
  - `/data` — экспорт, импорт, seed, очистка.
  - `/notifications` — уведомления о сроках техобслуживания.
  - `/logs` — история операций.
  - `/statistics` — агрегированные метрики для визуализации.

### Middleware
- `src/middleware/jwtMiddleware.ts` реализует JWT-аутентификацию через `jsonwebtoken`.
- `authenticate` проверяет заголовок `Authorization` и поддерживает форматы `JWT <token>`, `Bearer <token>` и сырой токен.
- JWT-токен содержит `userId`, `email`, `iat`, `exp`, срок жизни 24 часа.
- `src/middleware/errorHandler.ts` централизует возврат ошибок в JSON.

### Контроллеры
- Каждый модуль маршрутов делегирует работу контроллеру:
  - `AuthController`, `DataController`, `StatisticsController`, `UserController`, `LogController`, `NotificationController`, `UtilityController`.
- Контроллеры избавляют маршруты от прямой работы с БД и избыточной логикой.
- Ошибки пробрасываются в `next`, где их перехватывает `errorHandler`.

### Репозитории
- `src/repositories/*` содержат SQL-запросы и возвращают нормализованные сущности.
- Реализованы репозитории для пользователей, оборудования, компонентов, техобслуживания и логов.
- Репозитории поддерживают единообразные операции `get`, `insert`, `update`, `delete`.

### Сервисы
- `src/services/*` реализуют доменную логику:
  - `equipmentService.ts`, `maintenanceService.ts`, `componentService.ts`, `userService.ts`, `statisticsService.ts`, `notificationService.ts`, `logService.ts`.
- Сервисы используют репозитории и дополняют данные дополнительными вычислениями.
- Отдельный сервис отвечает за вычисление статистики и готовит данные для графиков.

### База данных и миграции
- `src/db/database.ts` подключает SQLite через `bun:sqlite`.
- `src/db/migrations/index.ts` описывает миграции для таблиц и триггеров.
- `src/db/migrationRunner.ts` запускает только новые миграции и хранит историю в таблице `MigrationHistory`.
- Таблицы: `Equipment`, `Component`, `Maintenance`, `User`, `ServiceLog`, `MigrationHistory`.
- Миграции устраняют необходимость ручной инициализации схемы при старте.

### Seed и тестовые данные
- `src/seed/seed.ts` реализует:
  - `seedTestData()` — наполнение базы тестовыми данными;
  - `exportData()` — выгрузку текущего состояния в JSON;
  - `importData()` — загрузку данных из JSON;
  - `clearAllData()` — очистку всех таблиц.
- Служит для быстрого локального развёртывания и настройки тестовой базы данных.

## Архитектурные решения
- Строгое разделение ролей: `route -> controller -> service/repository -> db`.
- JWT-авторизация вместо устаревшего формата токена.
- Миграции позволяют поддерживать схему в актуальном состоянии.
- Репозитории убирают SQL-логику из сервисов и контроллеров.
- Контроллеры обрабатывают HTTP и оформляют единообразные ответы.
- Тесты на Jest проверяют модульную и интеграционную работу.

## Реализованные улучшения
- JWT-авторизация с проверкой `Authorization`.
- `controller` слой для HTTP-обработки.
- `repository` слой для доступа к данным.
- Миграции для управления схемой базы.
- Автоматизированные Jest-тесты и интеграционные проверки.
- Статистика для визуализации на фронтенде.
